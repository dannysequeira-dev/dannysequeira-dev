## How I approach engineering

I work across the stack—from modeling business rules and designing service boundaries to shipping user interfaces, improving delivery pipelines, and operating software in production.

I gravitate toward **complex domains, reliable distributed systems, and developer experience**. My rule of thumb: make invariants explicit, keep boundaries intentional, verify behavior, and make failures observable.

## Featured open source: [Neshel-UI](https://github.com/dannysequeira-dev/neshel-ui)

**A modular, accessible React design system—built as independently installable packages, not a monolithic component library.**

Neshel-UI is published on npm (initial `0.1.0` release) and has five packages: configuration/tokens, layout, typography, components, and a build-time CLI. It supports plain CSS or optional Tailwind CSS v4 integration.

- **Architecture:** semantic design tokens, composable primitives, package boundaries, and documented decisions.
- **Confidence:** cross-platform CI, browser accessibility checks, packed-package consumer tests, and SSR/Next.js verification.
- **Developer experience:** TypeScript APIs, bilingual documentation, examples, and reproducible package distribution.
